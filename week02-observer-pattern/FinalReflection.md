# Final Reflection – Week 2: The Observer Pattern

The Observer pattern is a design where a subject keeps a list of observers and automatically notifies them whenever its state changes, so the subject and its observers stay loosely coupled. It is important because it lets us add, remove or change reactions to data (like the logger in Activity 3) without editing the code that produces the data, which makes programs easier to extend, test and maintain. It is the core idea behind event-driven programming: an event source publishes events, and any registered listeners respond when something happens, just like button clicks in a GUI. In this week's activities I saw it in several forms, from the custom weather station to the deprecated `java.util.Observable` and `PropertyChangeListener`. For my own plain Java project I would choose a custom Observer, because it is not deprecated, gives me full control over what data is pushed and how it is typed, and needs no extra libraries. If I were building a JavaFX application I would switch to JavaFX Properties and Bindings, since they handle change tracking for the UI automatically.
